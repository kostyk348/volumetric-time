# Объёмное время (Volumetric Time)

Исследовательская программа, выросшая из одной тетрадки Colab: **собственное время как сигнал управления обучением**. Каждый слой — а позже каждый токен — получает своё «объёмное время» `τ`, выведенное из геометрии его обновления: угловая часть шага (поворот признаков, очищенный от радиального сжатия), косинусная когерентность направления, ускорение и — на макро-уровне — спектральный эффективный ранг весов. По этим сигналам модель решает, когда **разгонять пластичность** (фазовый переход) и когда **замораживать** слой.

Репозиторий — это исходник как есть плюс инструменты, чтобы его можно было запускать и проверять без браузера. Ни одна строка исходных экспериментов не переписана.

## Что внутри тетрадки, по существу

| клетка | что происходит |
|---|---|
| 1 | базовая линия: `(a+b) mod 97`, MLP, AdamW; логируется `path` (суммарный путь параметров), `wn` (норма весов), `lv` (лог-объём = средний логарифм дисперсии по слоям) |
| 2–4 | поиск режима грокинга и три способа заморозки (включая честную заморозку через исключение группы из оптимизатора) |
| 5–7 | серии прогонов с разными гиперпараметрами, накопление статистики |
| 8 | `VolumetricTimeController`: локальный LR и «локальные часы» на слой, иерархия заморозки сверху вниз |
| 9 | `GeometricTimeEngine`: ортогональное разложение шага на радиальный/угловой, когерентность, ускорение, детектор фазового перехода, +30 % пластичности в критическом окне |
| 10 | `VolumetricTimeOrchestrator`: спектральный эффективный ранг как макро-структура и Z-score детектор фазы вместо ручных номеров эпох |
| 12 | та же идея на трансформере: `(a/b) mod 97`, мезо-роли Attention / MLP / Embeddings |
| 13–15 | `VolumetricTimeHackerV3–V5`, `SubspaceLinear` |
| 16 | переход на реальный текст: Tiny Shakespeare, char-GPT, иерархическая кристаллизация слоёв |
| 17–19 | `BallisticLanguageOrchestrator`, `HyperDriveOrchestratorV4`, `OmegaDriveOrchestrator`: RoPE, физический bypass выученных слоёв, «баллистический» шаг по инерции, замер **реального** времени и FLOPs |
| 20–22 | `VolumetricGPT` + `LowRankLinear`: факторизация после обучения, токен-уровневые заморозки, три режима инференса |
| 24 | компилятор в формат `Spectral-MMAP`: веса раскладываются по рангу, исходная модель удаляется из памяти, чтение с диска узкой полосой по потребности |
| 25–27 | `UnifiedVolumetricOrganism`: непрерывное спектральное поле (нейро-ODE с Фурье-модуляцией по `τ`), аттрактор в шаре Пуанкаре, автономный мета-контроллер `π(h, v_ang) → (ранг r, шаг Δτ)` на Gumbel-Softmax |

## Главная мысль, если убрать всё лишнее

Обычный оптимизатор видит один скаляр — loss. Здесь добавляется второй, дешёвый: **скорость поворота признаков**. Она падает не тогда, когда падает loss, а раньше и по-слоёвому. Из этого следуют три проверяемых утверждения:

1. **Угловая скорость опережает обобщение.** Пик `|Δv_ang|` наступает до того, как test loss падает — это и есть сигнал «сейчас окно пластичности».
2. **Замораживать можно по геометрии, а не по номеру эпохи.** Слой, у которого поворот упал и когерентность высокая, готов: полная заморозка для эмбеддингов, `×0.25` LR для скрытых, с сохранением weight decay.
3. **Из этого следует экономия вычислений, а не только ускорение сходимости.** Замороженный слой можно физически убрать из графа, а на инференсе — читать с диска узкую полосу спектра.

## Что здесь не доказано (честно)

- **Нет базовой линии в одном протоколе.** Каждая клетка — новая конфигурация; сравнение «с контролем / без контроля» есть внутри клеток 8–19, но между клетками гиперпараметры разные, поэтому складывать их в один график нельзя.
- **Один сид.** Нигде нет разброса по сидам, значит нельзя отделить эффект метода от удачного запуска. Это первое, что надо закрыть.
- **Грокинг — известное явление**, и «объёмное время» пока не отделено от простых суррогатов: `‖Δw‖`, норма весов, cosine LR schedule, ранняя остановка по validation. Пока не показано, что оно даёт больше, чем они.
- **Терминология.** «Объёмное время», «баллистический КПД», «собственное время слоя» — метафоры; в тексте они должны быть привязаны к формулам, иначе статья непроверяема.
- **WikiText-2 и tiny-модели** — это демонстрация механики, а не доказательство масштабируемости.
- Последняя клетка (29) в тетрадке была прервана (`KeyboardInterrupt`) — финальный прогон BPE-организма не завершён.

## Как запускать

```console
node tools/split.mjs list        # все клетки: индекс, строки, первая строка
node tools/split.mjs cell 19     # достать одну клетку в runs/19-....py
node tools/split.mjs all         # все клетки сразу
node tools/split.mjs selfcheck   # проверить, что файлы в runs/ совпадают с тетрадкой
```

Дальше — обычный Python-запуск: `python runs/19-....py`. Зависимости: `torch`, `numpy`, `matplotlib`, местами `datasets`, `tokenizers`.
