# Журнал прогонов: что измерено и что это значит

Все числа получены на этой машине, `cargo run --release`, без GPU и без Python. Журнал ведётся,
чтобы не повторять одни и те же тупики и чтобы выводы не оставались в переписке.

## Проверка, что сеть вообще рабочая

| прогон | train loss | значит |
|---|---|---|
| `P=11`, все пары, `dim 16 / hidden 48`, `wd 0` | **0.0020** | сеть запоминает данные целиком → обратный проход корректен |
| `P=31`, 30 % train, `wd 1.0` | 0.019 | запоминает 30 %, обобщения нет |
| `P=97`, 30 % train, `batch 128`, `wd 0.02` | 1.09 | частичное запоминание |

Предсказания на невиданных парах при `P=11`: модель выдаёт `a` или `b` — shortcut «скопируй вход»,
а не сумму. Это известное поведение фазы запоминания, а не ошибка реализации.

## Сетки, которые не дали грокинга

| конфигурация | прогонов | лучшая test acc | замечание |
|---|---|---|---|
| `dim 64 / hidden 96`, `batch 128`, 20k шагов, `wd 0.4` | 9 (3 руки × 3 сида) | 0.1 % | все руки бесполезны |
| `P=97`, `batch 512`, 8k шагов, `lr 1e-3`, `wd 1.0`, постоянный lr | 3 (сид 1) | 0.3 % | ближе всего к рецепту тетрадки, перехода нет |
| `P=31`, почти полный батч, `wd 1.0` | 2 | 0.0 % | запоминает и переобучается |

## Что известно про режим (и чего не хватает)

Тетрадка, по её собственному выводу: `lr 1e-3`, `AdamW weight_decay 1.0`, полный батч 2822
примера, 8000 эпох, эмбеддинг и скрытый слой по 128. К epoch 4000 train loss 0.0067, а test loss
начинает падать только к 6000–8000 (12.1 → 2.39).

Мои расхождения с этим режимом, от самого вероятного:

1. **Инициализация.** Было `N(0, 0.1)` для эмбеддингов; PyTorch по умолчанию — `N(0, 1)`. Норма
   весов управляет тем, какое решение находится первым, и в грокинге это не косметика.
2. **Мини-батч вместо полного.** 512 против 2822: градиент шумный, «поздняя» фаза сглаживается.
3. **Ширина.** 64/96 против 128/128: Фурье-представление суммы по модулю требует места.
4. **Расписание.** У них постоянный lr; косинусное, которое стояло по умолчанию, гасит как раз ту
   фазу, где происходит переход. Исправлено: теперь постоянный lr по умолчанию, `--cosine` — опция.

## Найденные баги (уже исправлены)

1. **Weight decay на каждом мини-шаге** при определении «на эпоху»: за 100k шагов веса умирали
   (`e⁻¹⁰⁰`), модель не училась вообще. Теперь decay трактуется как в AdamW — на шаг оптимизатора.
2. **Контрольная рука `randfreeze` не срабатывала ни разу**: период заморозки считался от
   `log_every` и превышал длину прогона, то есть контроль был тождественен baseline. Теперь период
   считается от длины прогона.
3. **Косинусное расписание по умолчанию** (см. пункт 4 выше).

## Что делать дальше, по порядку

1. Прогон с инициализацией как в PyTorch (`N(0,1)` для эмбеддингов) при полном батче — запущен.
2. Если перехода всё равно нет — **численная проверка градиента**: центральная разность по каждому
   параметру на крошечной модели, сверка с аналитическим. Это единственный способ отличить «режим
   не тот» от «градиент не тот», и он дешевле трёх часов прогонов.
3. Если градиент сходится, а перехода нет — сверить один шаг с PyTorch на том же сиде: одинаковые
   веса после первого шага значат, что расхождение только в гиперпараметрах.
4. Только после воспроизведения явления сравнивать руки. До этого любые «v2 лучше» — шум.
